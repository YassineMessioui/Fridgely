# Repository agent instructions

## Development journal

The development journal is strictly opt-in.

- Do not create, edit, or append anything under `docs/development-journal/` unless the user's current message explicitly asks to document, log, or record project work, a session, or a decision.
- Requests to implement a feature, explain an approach, update an issue, commit code, or open a pull request do not imply permission to update the journal.
- Examples of explicit triggers include: “Document this session,” “Log this decision,” and “Add this to the development journal.”
- When explicitly triggered, read `docs/development-journal/README.md`, the entry template, and relevant existing entries before writing.
- Record only facts supported by the conversation, repository, or linked GitHub artifacts. Clearly distinguish decisions, proposals, experiments, and unresolved questions.
- Prefer a concise narrative that explains goals, tradeoffs, changes in direction, validation, lessons, and next steps. Do not copy raw chat or terminal transcripts.
- Never record credentials, tokens, secrets, private personal information, or sensitive command output.
- Link relevant issues, pull requests, commits, and architecture decisions when available.
- Update an existing entry when it covers the same session or topic; avoid duplicate entries.
- If the requested journal scope is ambiguous, document only the current session and state the assumed scope.
